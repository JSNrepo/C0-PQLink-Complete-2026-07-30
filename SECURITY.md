# Security policy

C0-PQLink 0.1.0 is an experimental research package. Do not deploy it in
medical, grid, automotive, payment, access-control, or other safety-critical
systems until it has received independent protocol and implementation review
and has passed measurements on the exact target hardware.

## Minimum deployment gates

- unique 32-byte PSK per device, generated by a CSPRNG;
- protected PSK and peer private-key storage;
- trusted provisioning of public key, key ID, and epoch;
- documented cryptographic RNG with health/failure behavior;
- target-linked disassembly review for secret-dependent control flow;
- stack high-water and SRAM measurements with worst-case interrupts;
- cycle, latency, energy, and radio-airtime measurements;
- malformed-input fuzzing and protocol state-machine review;
- power-loss tests for migration storage;
- key rotation, revocation, device replacement, and compromise procedures;
- third-party cryptographic review.

Never replace the random callback with `analogRead()`, timestamps, counters,
uninitialized memory, a fixed seed, or a non-cryptographic PRNG.

The client rejects all-zero PSK and key-ID placeholders, but it cannot detect
a reused fleet PSK or weak nonzero provisioning. Uniqueness and entropy remain
manufacturing/operations responsibilities.

## Reporting a vulnerability

Until a public repository and private disclosure address are assigned, do not
publish a suspected vulnerability with live secrets or affected-device
details. Contact the package owner through the hackathon/project channel and
include:

- affected version and target;
- minimal reproducer or trace;
- expected and observed behavior;
- security impact;
- whether public disclosure is already planned.

Add a private security contact before any public or production release.
